# AI Coding & Engineering Session Log

## 1. Problem Framing & Research-First Steering
- **Objective:** Design and implement a competitive, clean-container-reliable solution for the Xpert Winter Internship 2026 Cold Start Challenge (`https://goals.xpert.chat/w/intern`).
- **Environment & Materials Verification:** Inspected repository state, environment variables, connected Google Drive, and official download endpoints (`/w/intern/starter`, `/w/intern/data`). Confirmed both download endpoints returned `HTTP 500` and no `LLM_API_KEY` was pre-configured in the sandbox. Recorded this explicitly rather than fabricating official dev-set metrics, and engineered `src/schema_adapter.py` to dynamically introspect and adapt to field aliases when the official `starter.zip/schema.json` is dropped in.
- **Literature Synthesis & Architecture Critique:** Reviewed Zep/Graphiti (`arXiv:2501.13956`), Mem0 & independent Bench'd evaluations, GroupMemBench (`arXiv:2605.14498`), SpeakerMem-R1, MemOps (`arXiv:2607.12893`), APEX-MEM (`arXiv:2604.14362`), Microsoft AIMU commitment detection, PRISM (`arXiv:2602.01532`), TGL (`arXiv:2605.30152`), and FrugalGPT/RouteLLM cascades.
- **Key Architectural Pivot:** Critically challenged the initial `ContextGraph + LoopLedger` (11-state sequential FSM + unconditioned entity graph) concept:
  1. Unconditioned co-participation edges leak labels across heterogeneous WhatsApp groups (housing society RWAs, children's class parent groups, external client pilot groups).
  2. An 11-state sequential FSM compounds transition errors on terse multilingual WhatsApp replies where a single message (*"UPI kore diyechi"*) jumps directly from request to completion.
  - Selected **`Dossier-ARR-PRISM`** (Architecture D in `ARCHITECTURE.md`): dual-track verbatim index + `<180`-token speaker-grounded Contact Dossiers with domain-conditioned propagation + Anchor–Retrieve–Reconcile (ARR) temporal closure with 4 Asymmetric Closure Guards + PRISM expected-loss intervention policy.

## 2. Verification-Driven Debugging: Where Initial Code Was Wrong & How We Recovered
Rather than trusting first-pass heuristics, we built a rubric-faithful scorer (`scripts/checker.py`), a 20-case multilingual adversarial dataset (`scripts/generate_synthetic_suite.py`), and an 8-week, 1,403-message noisy multi-party stress suite (`scripts/run_experiments.py`). Automated evaluation exposed **five concrete bugs** that we diagnosed and fixed:

1. **Bug 1 — Cross-Chat Closure Bleed Across Duplicate First Names (`78.28 -> 84.79 / 86`):**
   - *Symptom:* Adversarial Case #14 (`Rahul Verma - Zephyr` vs `Rahul Electrician`) caused message `m112` in `Rahul Verma`'s DM to overwrite `m129`'s cancellation (`dropped -> done`) in `Rahul Electrician`'s DM via broad character n-gram similarity, and generic token `"update"` caused `Sneha`'s onboarding takeover to reassign ownership of a partner's investor-update task.
   - *Fix:* Restricted cross-chat retrieval in `src/temporal_resolver.py` to chats sharing an actual `person_id` (never matching by first name) and required $\ge 2$ non-name task-signature tokens for any cross-chat state transition.

2. **Bug 2 — Quote-Reply Status Checks & Reschedules Spawning Duplicate Loops:**
   - *Symptom:* Completion-check questions (*"Did you submit the October GST return?"*) and deadline moves (*"let's postpone and move the deadline to 5 Nov"*) quoting an earlier open loop were extracted as separate new loops, hurting `loop_precision` (`0.826 -> 0.950`).
   - *Fix:* Updated `src/loop_extraction.py` so status checks, postponements, and cancellations quoting an earlier message attach to the parent loop's evidence trail rather than creating duplicate loops, and scoped Hindi `"kal"` tense checks to a local 4-word window rather than the whole sentence.

3. **Bug 3 — Multi-Week Small-Talk Drift & Indian Polysemy (`"Silk Board"`, `"Pranam"`):**
   - *Symptom:* Scaling from 53 messages to 1,403 noisy messages across 8 weeks caused casual small-talk occurrences of *"dinner"*, *"Silk Board traffic"*, and festival *"Shubho Bijoya! Pranam"* greetings to accumulate raw keyword counts, misclassifying friends/siblings as `staff`, `partner` (*"board"*), or `parent` (`score_86` dropped from `85.5` on clean data to `75.8` on noisy 8-week data).
   - *Fix:* Replaced raw unnormalized token sums in `src/relationship_inference.py` with **distinct-term domain gates**, replaced single-word polysemous tokens (`"board"`, `"term"`) with unambiguous multi-word phrases (`"board deck"`, `"cap table"`, `"term sheet"`), and required parental vocatives (*"Pranam Maa/Baba"*) on festival greetings—lifting noisy 8-week performance to **`83.32 / 86` (`90.32 / 93`)** with `0` false `done` claims and `0` false `leave` interventions.

4. **Bug 4 — Inbound B2B Client Requests & Bridge Group Routing:**
   - *Symptom:* External contact `tarun@northstar` in `"Northstar x Zephyr Pilot"` was initially classified as `colleague` because the client *requested* a proposal rather than `ME` pitching one, routing the client group to `org_zephyr`.
   - *Fix:* Added `@domain` handle extraction, `ClientCo x MyOrg` bridge-group detection, inbound deliverable-request cues, and priority routing of single-client bridge groups to the `client` person before internal work-org matching.

5. **Bug 5 — Live-Interview Natural-Language Name Matching & Strict Schema `additionalProperties`:**
   - *Symptom:* `pytest` revealed that `"Sneha Iyer is actually my partner"` missed `"Sneha Iyer - Zephyr"` due to the `- Zephyr` tag, and strict alternate schemas with `"additionalProperties": false` rejected optional fields not listed in `properties`.
   - *Fix:* Added base-name stripping before `- OrgTag / @domain` in `src/corrections.py` and schema-property gating in `src/schema_adapter.py`.

## 3. Pass 3 — External Open-Source Benchmark Audit & Red-Team Optimization
- **Competitor & Adjacent OSS Audit (`2026-11-03`):** Re-audited GitHub (`gh search repos` and `gh api search/code`) and web literature for public `xpert-cold-start` submissions (still zero public competitor repos) and studied adjacent open-source personal executive & commitment engines—specifically **`SenteLabsAI/OpenExecutive`** (`packages/core/tests/unit/test_open_loops.py`), **`ADAMAMZAR/troth`**, **`NovasPlace/CSM`**, and **`phillippmueller/chat-export-for-whatsapp`**.
- **12 Root-Cause Red-Team Fixes Applied Across `src/`:**
  1. **IST Local Timezone Preservation (`src/data_loader.py`, `src/models.py`, `src/intervention_policy.py`):** Replaced naive `.astimezone(timezone.utc)` conversion—which shifted `01:30 AM +05:30` IST messages backward to the previous UTC date and caused off-by-one `"tomorrow"` deadlines—with dominant-offset local timezone normalization (`bundle.tz_suffix`) and TZ-preserving `remind_at` timestamps.
  2. **Zero Hardcoded Dev-Persona Strings (`src/conversation_index.py`, `src/loop_extraction.py`, `src/goal_extraction.py`, `src/intervention_policy.py`, `src/corrections.py`):** Removed all hardcoded `"arjun"` strings from `src/` (verified via `grep -rn -i "arjun" src/`) and implemented dynamic `me_aliases` discovery from 1:1 DM vocatives and direct replies to `ME`. Verified that renaming `ME="Karan"` while adding a colleague named `"Arjun"` preserves an identical **`85.543 / 86`** score and assigns `"Arjun, please send the staging server AWS logs"` to `p_colleague_1`.
  3. **20,000-Message / 320-Chat Scale Optimization (`src/conversation_index.py`):** Replaced full-corpus per-query `char_ngrams()` recomputation with a two-phase inverted-index BM25 + structural boost pre-filter followed by lazy-cached `self._ngram_cache` re-ranking on the top 80 candidates—completing **20,000 messages across 320 chats in `1.20s`** (`1,506x` faster than the 30-minute container limit).
  4. **Live-LLM Compatibility, Connection Pooling & Budget Caps (`src/llm_client.py`):** Added automatic `max_completion_tokens` (`3x` reasoning headroom) + HTTP-400 capability downgrade for `o1`/`o3`/`o4`/`gpt-5*` reasoning models, `OPENAI_*` env-var fallbacks, persistent `httpx.Client` connection pooling, and `LLM_MAX_WALL_SEC`/`LLM_MAX_COST_USD` safety caps.
  5. **Thread-Scoped, Speaker-Authorized & PDF-Caption Closure Guards (`src/temporal_resolver.py`):** Inspired by `OpenExecutive`'s attribution guards, blocked group bystanders and replies quoting unrelated threads (`overlap < 2`) from closing/cancelling another owner's loop; added requester receipt (`"Received the trademark receipt"`) and banking-rail (`"Sorted from HDFC!"`) closures; and caught a real WhatsApp bug where forwarding a second unpaid bill PDF (`kind == "document"`, `"I'll pay the October broadband bill before 4 Nov"`) falsely closed an earlier unpaid bill!
  6. **Cross-Chat Loop Deduplication, Holiday-Home Org Isolation & Enum Schema Adaptation (`src/loop_extraction.py`, `src/organisation_inference.py`, `src/relationship_inference.py`, `src/schema_adapter.py`, `src/output_builder.py`):** Deduplicated cross-chat follow-ups (`inter >= 3` within `36h`), prevented `p_staff_villa` from leaking into `org_home`, refined B2B `walkthrough` client cues, added case/delimiter-insensitive `_match_enum` adaptation, and made `validation_repairs` telemetry non-aborting.
